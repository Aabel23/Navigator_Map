# Brief trước khi viết document

Sao chép phần này vào đầu bài mới; xóa gợi ý sau khi điền. Nếu chưa biết, ghi `chưa rõ` và chỉ hỏi những điểm làm đổi thiết kế.

| Câu hỏi | Trả lời |
|---|---|
| Người đọc là ai, họ biết gì rồi? | |
| Sau khi đọc, họ cần hiểu/quyết định/làm gì? | |
| Câu trả lời chính trong 1–2 câu? | |
| Phạm vi và ngoài phạm vi? | |
| Nguồn chuẩn hiện tại (file, dữ liệu, người chốt, ngày)? | |
| Hệ thống/quy trình hiện chạy ra sao? | |
| Thay đổi/đề xuất là gì, vì sao? | |
| Một tình huống đại diện có đầu vào và đầu ra cụ thể? | |
| Ai/cái gì tham gia; ranh giới, dữ liệu và quyền sở hữu? | |
| Khi hỏng, chậm, trùng hoặc mất kết nối thì sao? | |
| Quyết định đã chốt; giả định; câu hỏi còn mở? | |
| Bằng chứng/phép kiểm để nói là đạt? | |
| Định dạng đầu ra, mức dài, có cần cập nhật live/in/PDF không? | |

## Sổ khẳng định

Trước khi dựng sơ đồ, ghi các khẳng định dễ bị hiểu là đã chốt. Dùng nhãn chính xác: `hiện trạng`, `đã chốt`, `đề xuất`, `giả định`, `chưa kiểm`.

| Khẳng định | Trạng thái | Nguồn/ngày | Kiểm hoặc điều kiện chốt |
